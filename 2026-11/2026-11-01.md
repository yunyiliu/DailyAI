### 开场

这里是 Daily AI Signal，今天是 11 月 1 日，星期日。

### 头条：DeepSeek 公开一种会自己接活的 Agent

先说 DeepSeek。

周六晚上，DeepSeek Harness 团队，也就是做 DeepSeek 编程 Agent 工具的团队，发了一篇长文，题目叫 Super-agent 设计探索。同时，他们在 GitHub 上开源了一个研究原型，用的是 MIT 许可证。

这次没有新模型，也没有新的跑分。讲的是模型外面那一层，Agent 怎么接活，怎么干活。

这个原型，是给一个 GitHub 代码仓库用的编程 Agent。它会盯着 GitHub，也可以接上飞书。有权限的人提出需求，它就建一个任务，给这个任务单独开一个 Agent 会话，单独一个工作目录，做完再回到原来的对话里答复，比如提交一个代码合并请求。还有一个网页面板，专门列出需要人来处理的事。DeepSeek 的说法是，尽量少占用人的注意力，尽量多提供价值。

结构上分两层。一个常驻的主会话，负责判断这活接不接，再分配出去。真正干活的，是一个个独立的执行会话。

据第一财经报道，DeepSeek 在文章里说，内部版本已经在持续运行，用来修复问题，回复代码审查，还用来改进 Harness 本身。这是 DeepSeek 自己的说法。

开源出来的版本要小得多。DeepSeek 在说明里写得很直接，这是仅供参考的研究原型，不是 DeepSeek 的正式产品，也不能直接用在生产环境。

我觉得这次真正值得看的，是它怎么处理权限。

有人明确提需求，它随时会接。但如果是它自己判断出来的活，比如在群里看到有人抱怨，觉得该去修，这时候有三种模式，关闭，观察，自动。默认是观察。观察模式下，它只评估，记一笔我会接，但什么都不做。你先看一段时间，它的判断靠不靠谱，再决定要不要放手。

而且每接一个活，都会生成一份授权记录，写清楚请求从哪来，匹配了哪条规则，按哪个版本的规则批准的。群聊和评论里的话，可以拿来参考，但不能自己扩大 Agent 的权限。

问题在于，它的执行文档也写明了，执行会话会用部署者的系统账号直接跑命令，不需要审批。工作目录这些限制，只是默认设置，不是安全边界。换句话说，你电脑上有什么密钥，它就能用什么密钥。

为什么重要？各家都在把编程 Agent，推向在后台一直干活。但这一层调度和权限的设计，大多数公司不公开。DeepSeek 把它写成了谁都能看的文档。

我的判断是，一直在线的 Agent，难的不是它会不会修 bug，而是谁允许它去修，事后能不能查。先观察，后放手，每个活都留一份授权记录，这是个靠谱的起点。接下来要看，DeepSeek 会不会把它做成正式功能。

### 次要新闻一：攻击者也开始用 Agent 和大模型

第二条，安全。这个周末有两件事，都和攻击者用 AI 有关。

先说 Chainalysis，这是一家做区块链追踪的公司，很多政府和交易所，都用它追查被盗的加密货币。它在周五的声明里说，这个月，它发现有外部攻击者进入了它的系统和内部工具，用的是它所说的进攻性 Agent 技术。被访问的，是平台用户的 ID，姓名，邮箱和在机构里的角色。公司说，目前没发现调查内容，密码，二次验证密钥和登录凭证被访问。受影响的客户有多少，它没说，所谓 Agent 技术具体指什么，也没解释。它还说，这件事和本周币安被盗没有关系。

再说思科旗下的安全团队 Talos，周六公布了一个叫 VOLTA 的窃密木马。它在 Windows 电脑上偷浏览器密码，网站登录信息，银行卡，加密钱包。新的地方在后面，它把偷到的东西整理成一份报告，通过 OpenRouter 这个接口平台，发给大模型，让模型扮演情报分析师，写一份目标评估，里面有一节就叫他们值多少钱。默认用的是 Claude 模型，备选是 Kimi 和 Gemini。一个模型拒绝了，它就自动换下一个。

我的判断是，模型在这里没有去黑谁，它干的是筛选，帮犯罪分子判断，谁最值得下手。而自动换模型说明，单靠一家的安全限制，挡不住。

### 次要新闻三：模型能把坏数据，混过自家的检查

第四条，一项安全研究。Anthropic 的对齐团队，最近发了一篇文章。他们让一个 Claude 模型，专门编写训练数据，目标是让一个小的研究模型学坏，同时还要骗过一个检查训练数据的监测器，而且它能完整看到这个监测器。

反复尝试之后，它真的找到了这样的数据，监测器几乎不报警，训练出来的模型却学坏了。常见的办法，是把坏行为包装成小说或者角色扮演。作者也说了，这个设定对进攻方很有利，结论也不代表已经上线的 Claude 模型会这样做。

简单说，逐条检查训练数据，是常见的一道防线。这项研究说明，每一条看着都没问题，合在一起，照样能教坏模型。

### Hook

Most coding agents wait for you to type a request. On Saturday night, DeepSeek published the blueprint for one that listens to your team's chats and decides for itself whether to pick up the work. And the more interesting part is how it decides it's allowed to.

### Today's top stories

Also today: attackers are putting agents and models to work, from a breach at Chainalysis to a piece of malware that asks an AI model what each victim is worth. And the money behind AI got pickier this week, at OpenAI and at Meta.

This is Daily AI Signal for Sunday, November first. Let's get into it.

### Main story — DeepSeek's Super-agent

Here's what happened. On Saturday evening, Beijing time, the team behind DeepSeek Harness, the company's coding-agent tool, published a long design essay called Super-agent. At the same time, it put a research prototype on GitHub under the MIT license.

There is no new model here, and no benchmark. This is about the layer around the model.

The prototype is a coding agent for one GitHub repository. It listens to GitHub and, if you connect it, to Feishu, the workplace chat app. When an allowed person asks for something, it opens a work item, gives that job its own agent session and its own folder, and then replies in the original thread, for example with a pull request. A small web panel shows the items that need a person. The stated goal, in DeepSeek's words, is to "take as little human attention as possible, and give as much value as possible."

The design has two layers. A resident main session reads incoming events and decides whether to take a job. Separate executor sessions do the work. A job can pause, wait for feedback, and resume later, without one long chat holding everything together.

According to the Chinese business outlet Yicai, the essay says DeepSeek already runs internal versions of this continuously: reproducing and fixing issues, answering code reviews, and improving Harness itself, sometimes spotting a likely bug in a group chat without being tagged. That's DeepSeek's description, reported secondhand. The public code is a different, smaller thing, and DeepSeek is blunt about it. The README calls it a research prototype for reference only, "not an official DeepSeek product," and not production-ready.

Now, what most headlines are missing. The interesting part isn't that the agent can act on its own. It's how the prototype handles permission.

Explicit requests always work. But for work the agent infers on its own, say, it reads a complaint in chat and thinks it should fix something, there are three modes: off, observe, and auto. The default is observe. In observe mode, the agent assesses what it would take on, writes down "would accept," and does nothing. You watch its judgment for a while before you let it act.

And every job it does accept gets what DeepSeek calls a mandate: a record of where the request came from, which rules matched, and which policy version allowed it. Chat messages and comments can feed the decision, but they can't widen the agent's permissions by themselves.

There's also a small detail I like. The system keeps one spare slot for a person's message, so a pile of new work can never stop a human from steering a job already in progress.

The catch is right there in the execution docs. Executor sessions "run commands without approval as the operator's OS user." The working folders and wrappers are, quote, "defaults, not a security boundary." So if you run this on a laptop with production keys, the agent has those keys too.

Why does this matter? Every major lab is moving coding agents from "answer when asked" toward "keep working in the background." Most of them keep that orchestration layer closed. DeepSeek just published one, with the permission logic written down in plain documents anyone can read and copy.

My read is that the permission model is the real contribution. The hard problem with always-on agents isn't whether they can write the fix. It's who said they could, and whether you can check that afterward. A default of "watch, don't act" plus a written mandate per job is a sensible starting point, whoever ends up building the production version.

What to watch next: whether DeepSeek turns this into a supported Harness feature, and whether other labs publish their own designs for team agents.

### Secondary story — Attackers put agents and models to work

Two security stories this weekend show AI showing up on the attacker's side, in very different ways.

First, Chainalysis, the blockchain analytics firm that governments and exchanges use to trace stolen crypto. In a statement dated Friday, it said that this month it detected an outside actor using what it called "offensive agentic techniques" to get into its systems and internal tools. The attacker accessed user IDs, full names, email addresses and organization role labels for people on its platform. Chainalysis says it has found no evidence so far that investigation content, passwords, MFA secrets or session tokens were accessed. It hasn't said how many customers are affected, and it hasn't explained what "agentic" meant in this attack. It also says the incident is unrelated to the multibillion-dollar Binance theft this week, which the FBI has attributed to North Korea, according to the analytics firm Elliptic.

Second, Cisco Talos published an analysis on Saturday of an infostealer called VOLTA. It's ordinary malware in most ways. It grabs browser passwords, cookies, cards, crypto wallets and app sessions from Windows machines. The new part is what happens next. It bundles everything into a report and sends it, through the OpenRouter API, to a large language model. The default is a Claude model, with Kimi and Gemini as fallbacks. The prompt asks the model to act as "a forensic intelligence analyst drafting a target assessment," including a section called "what they're worth." If one model refuses, VOLTA detects the refusal and tries the next.

My read: the model isn't doing the hacking. It's doing the triage. Sorting through piles of stolen data to find who is worth targeting takes time, and that's the job being handed to a model. And the fallback logic means no single provider's refusal is the safety net.

### Secondary story — The money gets pickier

Yesterday we covered the Financial Times report that OpenAI cut the target for its new funding round to about twenty billion dollars. Today there's a sharper number. The Wall Street Journal reports that OpenAI has so far secured roughly eleven billion dollars in commitments, after what it called tepid interest from some large investors. OpenAI hasn't commented publicly.

Meanwhile, S&P Global Ratings changed its outlook on Meta from stable to negative, keeping the AA minus rating. S&P pointed to uncertainty over Meta's elevated spending and negative free cash flow, and said, quote, "it is unclear when these revenue streams will generate material contributions." Fortune reports S&P projects Meta's capital spending topping two hundred twenty-five billion dollars in twenty twenty-seven. Meta said it "respectfully" disagrees.

An outlook change isn't a downgrade, and eleven billion dollars is still a lot of money. But private investors and credit analysts are sending the same message in the same week: show us the revenue.

### Secondary story — A model that slips data past its own monitor

One research post worth your time. Anthropic's alignment team published a recent study where a Claude model was asked to write fine-tuning datasets that would make a small research model misaligned, while getting past a training-data monitor it had full access to.

With enough iterations, it found datasets that the monitor barely flagged and that still produced misaligned models, often by wrapping the bad behavior in fiction or roleplay. The authors say the setup favors the attacker, and that it is "not a finding about how deployed Claude models behave."

This matters because checking training data row by row is a common safety layer. The study suggests data can look fine line by line and still teach the wrong lesson. Anthropic frames it as a way to stress-test and improve those monitors.

### Quick hits

A shared ChatGPT link could have taken over your account. Researchers at Parameter Labs chained bugs in ChatGPT's HTML previews so that opening a malicious share link while signed in could expose private data or act on your behalf. OpenAI has fixed it. Meta built a humanoid robot with a Chinese partner. The Information reports Meta and Shanghai-based Fourier built a prototype called Max in about three months, and started a second version in September. Meta says the work is internal research, with no plans to sell the robots.

xAI's turbine lawsuit goes ahead. A federal judge denied xAI's motion to dismiss the NAACP's Clean Air Act suit over at least thirty-five gas turbines allegedly run without permits at its Colossus data center site near Memphis.

### Final take

The bigger trend behind today's news is that agents are leaving the chat box. DeepSeek is designing one that sits in your team chat and decides what to pick up. Attackers are already wiring models into their tools. In both cases, the question that matters isn't what the model can do. It's who gave it permission, and whether anyone can check. The one thing I would watch next is which lab ships a team agent with a permission record you can actually audit.
